Kit Guide — what is in this kit and what each part does

Read this once, top to bottom, before your first project. It explains every file and folder in the kit, who fills it, at which step, and why it exists. For the step-by-step playbook, open 00-workflow-map.html.

1 · The big picture

You bring a brief and a few assets. Claude turns them into research, a visual direction, design tokens, a full UI, and finally a Figma file with real components and a clickable prototype — in 8 phases and 17 steps. After each phase there is a gate: you review and approve before anything moves on.

Brief + assets→Research→Structure→Visual direction→Tokens→Final UI→Figma→Prototype + handoff

Three things make the kit work: the folders hold every result in a fixed place · the base prompts in _prompts/ tell Claude exactly what to do in each step · _progress.md remembers where the project stands, so any new session can continue.

YOU = you add or do it   CLAUDE = Claude writes it   GATE = you approve

4 · _prompts/ — the base prompts

One prompt per step: 01-intake.md … 17-handoff.md, plus a README.md with the rules they all share. They are the base — identical in every project and never edited for one. You do not paste them anywhere: Claude opens the right one at each step.

A base prompt contains no project details. It says which files to read, and the project's details come from there — so the same prompt works for a café app and for a car-rental app.

Every prompt has the same parts
ReadsThe files this step uses (brief, earlier outputs, tokens…).
Stop ifConditions that block the step — e.g. the previous gate is not approved, or assets are missing. Claude says which one and stops.
DoThe work, in numbered order, with table templates.
OutputThe exact file and its structure.
CheckA checklist Claude must pass before handing back. Anything with a number is measured by running code, not guessed.
End of turnA short report in a fixed format, then Claude stops.

Step 15 (Figma components) has the longest prompt: inventory first, 3–5 components per turn, each component checked before the next — because that is where things go wrong most often.

6 · How a session runs

You typeWhat happens
Read FolderFirst time: Claude checks your brief and assets, shows a ✅/⚠ table, repeats back what it understood and asks to start. On a project already under way: Claude reads _progress.md and tells you where you are.
continueClaude runs the next step from its base prompt, saves the output, updates _progress.md, reports and stops.
approvedAt the end of a phase: Claude records the gate as APPROVED in _progress.md. The next phase can now start.
Every step ends with the same short report
STEP 07 · Colour palette — done
Files:        03-research/07-palette.md · 07-palette-options.html
Key result:   3 palettes from the logo; option B recommended
ASSUMPTIONS:  2   ·   [BLOCKER] questions: 0
Measured:     contrast computed — 1 pair fails in option C
_progress.md: updated
Next:         Step 08 · Moodboard — say "continue" to run it
Changed your mind about an earlier step?
Say so. Claude re-runs that step, marks every step built on it as stale in _progress.md, and re-opens the gate — so nothing old slips through.

7 · The rules that keep the result clean

You are the director

Claude works fast; you approve every phase. Nothing passes a gate without your "approved".

No guessing

Anything not in the brief is marked ASSUMPTION. Questions go to the client; blocking ones are tagged [BLOCKER].

Test small first

5 proof screens before the full UI. Most quality is decided in Steps 01–06.

One source of truth at a time

Proof screens → first tokens. Final UI → Primitive & Semantic tokens. Real Figma components → Component variables.

Assets as given

Logo, icons and font used exactly as provided — never redrawn. Only fonts and icons you may use commercially.

Screen codes never change

S01, S02… are fixed once created, because every later file and the Figma file point to them.

Don't edit: CLAUDE.md · _prompts/ · _progress.md (Claude keeps it). You edit: 01-brief/ · 02-assets/ · and you answer, choose and approve at every gate.
